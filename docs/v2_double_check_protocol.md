# v2_double_check_fintuned：搜尋與驗證規格

本輪先確保帳務及已量測交易限制正確，再比較參數。輸出是 `DEVELOPMENT_ONLY_NO_UNSEEN_HOLDOUT` 研究候選；正式 policy 維持 `UNKNOWN_BLOCK_SUBMISSION`，詳見[規則覆蓋](v2_double_check_rules.md)。

## 問題與決策

**問題：** 用相同固定 v2 A 核心、資料、費稅與官方股數公式，在新增違規回退帳本後，能否找到完整期間零已量測違規、優於既有候選的參數？

**假說：** 一部分舊候選因結算現金、價格情境或公司行動而失去資格；加入全軸覆蓋與配對抽樣可找到更好的可行區域。最強替代解釋是從已看過的行情挑中噪音，因此任何報酬提升都只支持開發期工程比較，不支持未來超額報酬或全域最佳。

**決策：** 不合格候選直接剔除；無合格候選就輸出 `NO_ELIGIBLE_WINNER`，不降低限制。合格者按期末帳面 NAV 報酬降序、MDD 升序、雙邊換手率升序、候選 ID 排序。權威是 [eligible／choose](../src/double_check_tuning.py)，不是人工選圖。

## 變數與固定條件

| 角色 | 變數 | 處理 |
|---|---|---|
| 比較變數 | `four_hour_mode` | 配對兩模式 |
| 調參變數 | 持股數、換股、門檻、指標窗 | 全軸值＋Sobol |
| 條件變數 | return／EMA／MACD 組合 | 以合法組合抽樣 |
| 固定策略 | v2 A | 不加其他策略族 |
| 固定成本 | 費 0.1425%、賣稅 0.3% | 不調降成本 |
| 固定規則 | 千股、150 檔、持股現金限制 | 不作調參變數 |
| 固定資料 | 2025-01-02～2026-09-21 | 417 交易日 |
| 固定可用性 | 前日決策、當日官方 VWAP | 禁當日改單 |

18 個設定及完整離散範圍由 [prepare_double_check.design](../scripts/prepare_double_check.py) 生成為 `config/v2_double_check_study.json`。長期 EMA、4H 指標窗、成熟條件、暖機與量比／波動估計窗沿用固定規格；這些固定值並未證明最優。回測是確定性流程，重跑用來驗證重現性，不把同一路徑的重跑冒充獨立市場樣本。

## 搜尋到底覆蓋什麼

原始離散全域笛卡兒積為 **36,303,120,000** 組；這還不含任意連續數值或所有可能策略。宣稱「全部可能參數已搜完」不成立。本輪預先宣告有界搜尋，凍結 global 設計共 **714** 個不同候選；下表是預定覆蓋契約，實際完成數以驗證報告為準。

| 階段 | 覆蓋契約 | 限制 |
|---|---|---|
| 舊設計重跑 | 405 組舊候選 | 新帳本重新計算 |
| 全軸值 | 每軸每值繞 incumbent | 非所有交互組合 |
| Sobol | 128 nuisance × 2 模式 | 單一固定 seed |
| 局部網格 | 7 軸 × 2 值＝128 組 | 只窮舉此子空間 |
| 另一股票池 | 同候選同參數 | 不另挑冠軍 |

Sobol seed 固定 `2026092301`；兩個 4H 模式共用 nuisance 設定。先前舊設計及單軸覆蓋不一定完全配對，因此不能拿全體不等量的 mode 最大值推導 4H 因果優勢；需要做此比較時，只分析本輪配對子集。

局部父代是 global 搜尋中 `official_ex_post` 的最佳合格候選。每軸取父代值與下一離散值；若在上界則取前一值。七軸為 `target_count`、`one_day_chase_return`、`return_pair`、`ema_pair`、`macd_tuple`、`cash_guard_ratio`、`four_hour_mode`。128 個位置必須全部映射到已完成候選；重複配置可復用同帳本、同程式、同資料的結果，不可漏記覆蓋。

**邊界解讀：** 最佳值落在上下界時，結論只能是目前範圍的最佳候選；未擴界不能宣稱內部或全域最優。單軸圖是條件敏感度，聯合 Sobol 圖是觀察關聯，均不能單獨識別機制。

## 資料、對照與選擇偏誤

`official_ex_post` 使用事後公布的競賽 150 檔，作本輪選參情境。`historical_pit` 作固定參數敏感度對照；不能在兩池各選最高報酬再當成同一策略。2026 年名單放進 2025 年回測有 membership lookahead，這不是當時可部署績效。

417 日全段已參與歷次開發，切成年份或 rolling windows 仍是開發期診斷，不能重新命名成 untouched test。Incumbent 必須用新帳本重跑；原 v1／0050 對照只有在資料、費稅、價格及 NAV 口徑一致時才可引用，否則另列口徑差異。這不是對各策略族投入相等 tuning 預算的科學排名。

**來源事實：** Bailey 等人的 [The Probability of Backtest Overfitting](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf) §1–2 討論在固定歷史上反覆選參所造成的假陽性與樣本外退化，並提出 PBO／CSCV 框架。

**本案推論：** 搜更多組只提高搜尋覆蓋，不會讓已使用資料重新獨立。因此本版記錄試驗數量、失敗及搜尋邊界，保留開發期標籤；未實際運算 PBO 或 CSCV，不提供虛構的過擬合機率。alphaXiv MCP 與可搜尋的 app 工具在本次工具清單未提供，故改讀作者原文；文獻不作競賽規則權威。

## 合格條件與帳務差異

每個候選必須完成宣告期間、未失格、指標有限，且下列八計數全部明確為零：`raw_rule_breach_days`、`measured_hard_breach_days`、`no_valid_plan_days`、`unfilled_orders`、`simulated_warning_days`、`stale_held_price_days`、`hold_without_envelope_days`、`execution_price_bound_breaches`。缺欄位與 NaN 不視為零。`raw_rule_breach_days` 包含所有單股超限日，即使該日仍在官方被動超限寬限期，也不能入選。

八個計數包含比官方更保守的研究門檻，例如價格情境超界與零超限日。這是本版主動收緊的選參條件，不能誤稱官方取消了五日寬限。合格狀態只表示通過本輪已量測 gate；AS 仍是 UNKNOWN，沒有正式收件紀錄的歷史日也不能模擬成已成功提交。

新帳本把當日多項一般違規合成一次警告，撤銷所有當日成交及費稅，第三次即停止。被動單股超限有五交易日寬限，加碼超限立即警告。回退保留公司權利與期末股利另外加 NAV 的細部順序屬研究假設，官方未確認；可觀測的會計差異須與舊版分開說明。

**超限歸因修正：** 「當日沒有買進該股」不能證明超限只由價格造成。例如賣出另一股票產生費稅，會降低組合 NAV，讓原有股票超限。修正採同日收盤、保留公司行動後的「完全不交易」組合作反事實比較；不交易仍合規、實際交易後才超限者不能取得價格被動寬限。這是本地保守歸因，官方對此邊界例未另有明文；正式選參另以零超限門檻排除對寬限解釋的依賴。

## 執行與停止條件

凍結本輪設定、資料、原始文件與程式 hash，將輸出隔離在 `outputs/v2_double_check_fintuned/`。每次候選保存狀態、設定、日帳本、委託／成交／退回成交、每日合規及規劃器記錄。失敗或中斷結果不參與排名，續跑前先核對指紋，不重用不明版本。

本輪首次搜尋因獨立反例發現上述超限歸因錯誤而暫停，舊產物隔離。受影響的結果不得重用或計入可信候選；修正後須通過費稅誘發超限、純價格波動、加碼超限與第六交易日等反例，再凍結新程式指紋重新搜尋。此紀錄描述工程恢復，不構成策略失效或最終績效結論。

研究停止條件是所有凍結 global 候選與 128 個 local 網格位置有終態、獲選候選重跑完成、獨立稽核完成。若基礎帳務測試失敗，先修復並重建受影響結果；若沒有合格候選，停止並如實報告，不臨時放寬規則尋找冠軍。

獨立驗證應核對費稅、逐日 NAV、持股股數、官方股數公式、警告回退、完整日數與無非法值；物理移除未來資料後重跑前綴，確認既有訊號與委託不變。結果摘要應含候選數、實際覆蓋、失敗原因、基準同口徑比較、邊界與參數敏感度，且明示全部正式阻斷項。

**採用規則：** `ADOPT` 只能指通過稽核的研究 incumbent；未來表現證據不足為 `HOLD`；正式部署在[規則阻斷項](v2_double_check_rules.md)全數解決前保持禁止。Git commit／push 保存研究工作，不等於向競賽提交政策。

本版 `plan` 不匯出政策；`research-plan` 產生有包裝的 `RESEARCH-DRAFT_…json`。即使本地帳務或結構測試通過，也不能以修改狀態旗標開啟正式送件。具體行為由 [daily adapter](../daily_auto/double_check.py) 與[回歸測試](../tests/test_double_check_daily.py)定義。

## 本輪校準原則

**證據：** 辦法 p8 六(十三)要求 Active Share，但本地官方檔只有 30 ETF 名單，未提供每日權重與完整算法；`validate_plan` 與新帳本均保留 UNKNOWN。**結論：** 可觀測規則零違規，不能替未知契約背書。日後報表或 policy 發布仍須分別檢查資料、算法、營運收件與實際結算，不能拿歷史高報酬或全部測試綠燈代替官方規則覆蓋。適用邊界是外部規格或輸入缺失；已取得並獨立驗證的證據才可解除相應阻斷。
