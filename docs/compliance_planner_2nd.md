# 第二輪合規規劃器

`src/compliance_planner.py` 是第二輪研究使用的因果下單規劃器。它只讀訊號日收盤前已知的持股、現金、排名與收盤價，先決定整張股數，再由隔日 VWAP 撮合。規劃器已凍結；正式研究固定 `cash_guard_ratio=12%`、`cash_guard_headroom=2%`。

這套規劃器降低可預見的現金、檔數與權重衝突，但不構成官方合規認證。歷史 Active Share 與正式白名單仍未完整驗證，提交狀態維持 `BLOCK_SUBMISSION`。

## 規則如何排序

規劃器先保住可執行的硬限制，再處理策略訊號。每筆委託皆為 1,000 股的倍數，且股數在看到隔日成交價前固定。

| 優先序 | 行為 |
|---|---|
| 1 | 拒絕缺價持股 |
| 2 | 守住 20–30 檔 |
| 3 | 修正單股上限 |
| 4 | 保留現金緩衝 |
| 5 | 執行訊號換股 |

若退出訊號會使持股低於 20 檔，規劃器會依當日既有排名，延後退出仍需保留的最高排名持股。這是規則優先例外，不代表退出訊號被取消。

例如，25 檔持股全部出現退出訊號，而且沒有合格新股時，規劃器先保留排名最高的 20 檔，讓其餘 5 檔等待可行退出。若賣出會使現金接近上限，它可先對這 20 檔加碼，建立現金餘裕，再於後續交易日重新評估賣單。

## 現金與價格壓力

正式設定的目標現金為 12%。現金硬上限按 `25% - 2%` 計算，因此規劃時的壓力上限是 23%。這是價格不確定性的研究緩衝，不是官方另設的 23% 規則。

規劃器用前日收盤價檢查三個角落：

- 負現金角落
  - 買價取 1.1 倍
  - 賣價取 0.9 倍
- 高現金角落
  - 買價取 0.9 倍
  - 賣價取 1.1 倍
  - 全部持股取 0.9 倍
- 集中度角落
  - 被測股取 1.1 倍
  - 其餘股取 0.9 倍
  - 現金採不利成交價

買賣手續費為 0.1425%，賣出另計 0.3% 證交稅。任何候選計畫只要在上述角落出現負現金、現金比例達 23%、持股檔數超限、非白名單持股或單股權重超限，就不會被當成完整可行計畫。

## 預付混合單

純買或純賣都無法解開「過重持股需賣、賣後現金又過高」時，規劃器才使用 `BUY_CASH_CAP_CORRECTION_PREFUNDED_MIXED`。這個備援比官方資金調度規則更保守：

- 買賣股票不重疊
- 買款由日初現金支付
- 買價以 1.1 倍估算
- 手續費一併預留
- 賣股不超過庫存
- 最終組合通過壓力

同一股票不會同日買賣，因此不形成同股當沖。官方辦法 §六（四）在 p7–8 直接舉出同日買進 2330 兩張、賣出 2454 一張的例子；[D-Plan 指南 §⑤](https://esun-ai-challenge.tw/api/events/fundaiagent/attachments/12/download/) 的 `funding_for` 也明定賣出可指向同日的 `BUY/ADD`。規劃器仍要求買單不用當日賣款即可支付，避免把尚未確定的賣出成交價當成買進資金。[競賽辦法 PDF](https://esun-ai-challenge.tw/api/events/fundaiagent/attachments/1/download/)

## Pilot 證據

修正版 pilot 共 12 組，期間為 2025-01-02 至 2026-09-21。獨立帳務稽核為 `PASS`，並依事前規則選定 12%：只要 A、B、C 的原候選在 12% 都是零個 measured hard-breach days，就固定使用 12%，不再用報酬挑現金參數。

| 原候選 | Guard | Hard-breach days | 不可行成交日 | 雙向換手 |
|---|---:|---:|---:|---:|
| A `p005` | 12% | 0 | 50 | 20.88x |
| B `p005` | 12% | 0 | 50 | 20.88x |
| C `p006` | 12% | 0 | 51 | 20.54x |

8% 的三個原候選也是零 measured hard breaches；16% 則在 A、B 各出現 1 日。事前規則指定「12% 全數為零即採 12%」，因此沒有用回測收益在 8%、12%、16% 之間追高。

這次修正解開了原 pilot 的檔數與權重死鎖，但不可行日仍多，換手也不低。不可行計畫會留下具名原因，不會被改寫為合規成功；它和官方警告次數不是同一概念。完整數值與帳務重算見 [`audit.json`](https://github.com/chrisPixelCraft/fintech_ETF/tree/dfd5f84) 及 [`trial_summary.csv`](https://github.com/chrisPixelCraft/fintech_ETF/tree/dfd5f84)。

獨立驗證的 17 項規劃器測試全數通過，全套測試為 109 項通過。範圍包含 production 混合單與 closed-form oracle 對照、完整價格角落枚舉、逐列帳務、預付金額篡改拒絕、同股交易與超賣拒絕，以及未來價格擾動與實體 prefix。12 組 repaired pilot 也全部通過帳務稽核，8 個混合單交易日的最大帳本誤差為 NTD 0.000001907。

## 邊界與失敗

壓力檢查只覆蓋事前宣告的 0.9–1.1 價格範圍。若實際市場超出範圍、停牌導致未成交、公司行動留下零股，或沒有任何整張委託能同時滿足限制，規劃器會回傳 `INFEASIBLE_*` 或保留殘股，不宣稱無條件保證。

目前證據只支持研究帳本與已量測規則。它不驗證市場容量、漲跌停排隊、歷史 ETF 持股、Active Share 或官方最終裁定。

舊 pilot 明細位於本機封存資料，Git 歷史保留當時程式。上方歷史連結只提供版本脈絡，不代表 Git 含有被排除的逐筆輸出；本輪結果以 full_tuned_v2 為準。
