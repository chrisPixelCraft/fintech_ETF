# 每日操作：照順序打勾

## 前晚：帳先對好

- [ ] 核對交易日
- [ ] 取得官方庫存
- [ ] 對上現金與 NAV
- [ ] 封存價量資料
- [ ] 封存 ETF 持股
- [ ] 檢查公司事件
- [ ] 恢復已結算的買賣階段
- [ ] 更新被動超限期限

19:00 後取得主辦方淨值表；指南另提供 `GET /api/portfolio/holdings/` 或後台庫存明細。必須先確認登入權限及真實回應格式，再建立讀取介面。若買單沒有成交，不能拿「原本預期買到」的股數作為明天庫存。

公司事件包含除權息、分割、合併及停牌。股息另外記應收，不拿來提前買股；配股造成的零股保留，遇到不明處理方式禁止猜測。

## 早上：Agent 做決策

- [ ] 固定程式版本
- [ ] 確認資料時點
- [ ] 產生完整 D-Plan
- [ ] 執行本機檢查
- [ ] 核對目標與股數
- [ ] 封存輸入與輸出

每次決策保存原始資料、SHA-256、程式、參數與提示詞版本。沒有 Git 也可用雜湊；只記版本名稱卻找不到實際程式不夠。美股資訊只有在當次決策前已發布才能使用；目前固定 A 不另加入美股條件。

現行入口為 `v2_offcial_best_deep_tuning.py plan`，固定 f0019。日 K 需已收盤，4H 只消費 09:00–13:00 四根已完成時線。現有持倉缺少可信前次計畫時不能重設狀態繼續交易；參見 [每日產單流程](full_tuned_workflow.md)。

## 送出：看回執

- [ ] 核對隊伍與日期
- [ ] 確認尚未過期
- [ ] 確認當日次數
- [ ] 上傳正確檔案
- [ ] 保存成功回執
- [ ] 核對收到的版本

建議 08:40 完成，08:45 再確認；08:55 是硬截止。PDF 允許前夜 19:30 起送件，schema 描述卻寫當日 05:00 起；在口徑未確認前，05:00–08:55 是兩者交集。前夜照常準備檔案。

上傳逾時時，先查有沒有成功紀錄，避免重複送件耗盡 25 次。重試沿用同日檔名，但每次都封存內容雜湊與主辦方回應。收到 HTTP 成功但沒有正式收件資訊時，不自動宣稱 `SUBMITTED`。

## 晚上：只記重點

| 欄位 | 用途 |
|---|---|
| NAV／今日損益 | 使用官方結算口徑 |
| 持股數／現金比 | 看檔數及現金限制 |
| 換手／成本 | 發現不必要的交易 |
| 一般警告累計 | 由官方結果確認 |
| Active Share | 各 ETF 值、最低值與連續低值天數 |
| 送件／資料錯誤 | 記錄原因及修復結果 |

不需要每天根據盈虧換參數。這個月最重要的是：同一策略可重現、資料沒有越界、送件有回執、帳本每天對得上。

## 故障處理

資料錯誤先修資料；程式錯誤先保留 log，再修程式重生報告。不要人工挑股票救火，也不要拿前一天 JSON 改日期交出去。修復後重新通過全部檢查，並保存新版本。

若無法在截止前得到可驗證的合規方案，維持阻擋並明確告警；不能把本機失敗標成主辦方成功。漏繳可能受罰，因此阻擋必須在早上提前發現，不能等到 08:54。
