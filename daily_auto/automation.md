## 已自動化

| 項目 | 本機能力 |
|---|---|
| 歷史計畫產生 | 從已稽核 A 自動產生 D-Plan 與同源訂單 |
| 每日固定訊號 | `v2_offcial_best_deep_tuning.py plan` 從原始日線與已完成時線計算，不接受手填排名 |
| 官方帳本對帳 | OperationsStore 僅採真正官方傳輸與已結算紀錄，覆蓋本地後二次核對 |
| 跨日策略狀態 | 以前次已接受 D-Plan、官方前後帳本及股數變化恢復待買入階段 |
| 被動超限期限 | 官方交易日、帳本估值與保守原因推論；缺失時不補造寬限天數 |
| 接收與配額 | 回執精確綁定內容，排除本機已知的較舊版本；最多 25 次的本機預留 |
| 官方格式 | 直接載入官方 schema v4 |
| 推導一致 | Decimal 計算目標整張股數，再比對委託 |
| 引用與覆蓋 | 檢查資料鏈、ID、每檔續抱／異動的交代 |
| 部位與現金 | 核對白名單、檔數、費用、權重與姿態 |
| 證據不足 | Active Share 等資料不全時明確阻擋 |
| 留存結果 | 產出本機檢查報告，拒絕覆寫不同內容 |

這些檢查不替代主辦方語意驗證器。若日後取得官方 `verify_dplan.py`，應再加一道官方驗證，不因本機通過而省略。

`python3 -m daily_auto.replay --output daily_auto/runs/my_replay` 可驗證從歷史計畫到 JSON 的完整本機流程。它不接受手動選股、不使用虛構新聞、不捏造 LLM 用量；正式交易還需要下節列出的資料與平台接入。

目前每日入口改用 [固定策略流程](full_tuned_workflow.md)；上述 replay 保留作舊版歷史示範。即使回執驗證層已寫好，也尚未取得真實平台成功回執。多次提交的主辦最終生效版本仍需官方結算契約，不能只靠本地回執清單推定。

## 還需要接通

| 缺項 | 接通後的驗收方式 |
|---|---|
| 帳號與隊號 | 實際隊伍資料與伺服器身份相符 |
| 官方持倉讀取 | 對上後台庫存、現金與 NAV |
| 即時行情更新 | 每個交易日前完整封存官方價量 |
| 30 檔 ETF 持股 | 時點、前十大權重及來源均完整 |
| AS 計算口徑 | 確認聯集、正規化與資料日期規則 |
| 平台提交 | 官方接口、驗證結果與回執皆可重現 |

資料夾沒有登入憑證；不要把密碼或 Token 寫進 JSON、README 或研究輸出。官方指南提供了持倉 API 路徑，但沒有提供提交 API 規格，不能猜端點並對外送單。

## 排程建議

前晚 19:35 對帳與抓資料；06:30 產計畫；08:30 最終檢查；08:40 送件；08:45 核實回執；19:00 後記帳。每一步寫狀態檔與 log，只有前一步完成且資料日期一致才往下跑。非交易日停止交易流程，但可做資料維護。

同一隊伍、同一交易日只允許一個執行者，避免重複下單。重跑需檢查既有檔案雜湊和回執；有相同成功回執就不再提交。不應用自動化工具持續重试未知失敗，直到撞滿每日 25 次。

若要交給排程器，先完成上述接入驗收，再啟用。這次沒有建立桌面自動工作、cron 或常駐服務；因此電腦休眠、登入失效、網路斷線等情況還沒有正式運行保證。

## 留存規格

每個交易日保存：原始輸入、來源時間、前日官方帳本、程式與參數雜湊、D-Plan、驗證報告、主辦方回執及收盤核對。舊檔不可直接覆寫；同日重送用版本子目錄保存，再複製成主辦方要求的固定檔名。

警告累計只採官方紀錄。Active Share 必須保存逐基金結果和資料時點；缺一天不能當作 0 次違規或自動中斷連續低值計數。歷史回測產出不可塞進正式帳本。
